# Security Policy & Deployment Guidelines

## Security Invariants

1. **Deterministic Scam & Threat Analysis**: Input messages are parsed locally. PII redaction previews are computed deterministically. The application does not visit untrusted target URLs and does not persist unredacted message text in PostgreSQL databases.
2. **AI Inference & Spending Gate**: In production environments and public Demo instances, direct external model invocations remain gated behind `deployment_gate` (`AI_LOCAL_ONLY=true`). Public Demos default to **Rules-only** mode, ensuring 100% predictable zero-cost execution and zero external provider exposure. In self-hosted setups with explicit opt-in, model calls require configured endpoints, strict structured schemas, full worst-case cost reservations, model cost ceilings, and fail-closed budget limits (`AiBudgetGuard` with PostgreSQL advisory locks). Honest actual costs, overages, and reserved ceilings are separately tracked (`migrations/017_ai_budget_accounting.sql`).
3. **Client Identity & Anti-Abuse Protection**: Client identities are hashed with a cryptographically secure salt (`OVERTO_CLIENT_IDENTITY_SALT`). When deploying behind reverse proxies, `OVERTO_TRUST_PROXY=true` requires verified socket peer IPs or `OVERTO_TRUSTED_PROXY_SECRET`. Unverified direct requests cannot evade rate limits by rotating headers; all untrusted requests map to a conservative shared bucket (`direct-untrusted-client`).
4. **Credential Isolation, Secret Scanning & Historical Revocation Notice**:
   - Database credentials, SMTP secrets, and API keys must never be committed to Git. Automated secret scanning (`npm run secrets:check`) runs in CI on every push and pull request across all tracked files.
   - **Historical Git Disclosure**: An independent security audit identified that early historical test files in releases `v7.0.0` and `v7.0.1` contained hardcoded test database passwords that matched local defaults. The compromised credentials were immediately rotated with a cryptographically secure 32-byte secret on the running PostgreSQL instance, and all current files were eradicated of secrets. The old password is completely invalidated and produces authentication failures (`FATAL: password authentication failed`) on all connection attempts. Because public Git history and historical tags (`v7.0.0`, `v7.0.1`) are intentionally preserved without force-pushing or history rewriting, historical commits retain the revoked credentials. They are verified non-functional in any active deployment.
5. **Account Lifecycle & Data Portability**: Account data exports (`/api/account/export`) support standard browser same-origin requests, reject cross-site invocations, and provide full historical records without arbitrary truncation. Account deletion (`/api/account/delete`) enforces password re-authentication, blocks root admin deletion, revokes all active sessions and keys, and cleans up workspace data within an atomic transaction.
6. **Financial Ledger & Stripe Refund Accounting**: All Stripe webhook operations are processed within atomic database transactions aligned with the credit ledger. Partial and full refunds are persistently tracked in `local_stripe_refund_tracking` (`migrations/018_stripe_refund_tracking.sql`) by workspace and invoice, retracting only the exact incremental delta of credits across multiple refunds, duplicate deliveries, and out-of-order events without double-deduction.

## Reporting a Vulnerability

For responsible disclosure, please contact the maintainer through GitHub Security Advisories or private security channels. Do not file public issues for unpatched vulnerabilities.
