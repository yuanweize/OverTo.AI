# Analysis API v1

This API is an experimental local interface. It does not verify the sender, prove fraud, or guarantee safety. Production authentication, complete visitor abuse controls and commercial billing are not available. **Do not expose it publicly.**

## Choose a request mode

| Mode | Authorization | Credits | Availability |
| --- | --- | --- | --- |
| Guest | None | Not metered | Local testing; rules by default, AI only with explicit consent and server configuration |
| Test key | `Bearer ovt_test_…` | One local test credit on successful rules or AI analysis; zero on AI fallback | Explicitly configured local account mode only |

A missing `Authorization` header selects the guest path. An invalid, expired or revoked bearer key returns 401; it does not fall back to guest. Test keys are not production keys. Keep keys out of source code and browser-distributed applications.

## Quick start

With the local server on port 3005, send synthetic text:

```sh
curl http://127.0.0.1:3005/api/v1/analyses \
  -H 'Content-Type: application/json' \
  --data '{"text":"Podezřelá zpráva", "enableLlm":false}'
```

For a local account, verify your email through the local test inbox, create a project key at `/dashboard/api-keys`, and place it in a shell variable without sharing it:

```sh
curl http://127.0.0.1:3005/api/v1/analyses \
  -H 'Content-Type: application/json' \
  -H "Authorization: Bearer $OVERTO_TEST_KEY" \
  -H "Idempotency-Key: $(uuidgen)" \
  --data '{"text":"Podezřelá zpráva", "enableLlm":false}'
```

A fresh `Idempotency-Key` is required for each keyed request. Reusing it returns 409 rather than a saved response. A successful keyed request consumes one test credit. Expired, archived-project and revoked keys cannot be used; the server stores a hash and prefix, not the full key.

## Request and response

`text` is required and limited to 10,000 UTF-16 code units; the request body is limited to 40,000 bytes. `enableLlm` is a boolean and defaults to false for guest requests; it must be provided for keyed requests. To request AI, set both `enableLlm` and `aiConsent` to `true` after the user consents to processing by the configured model provider. Server redaction is best effort: review and remove sensitive data before sending. Results are ephemeral and contain `schemaVersion`, `analysisId`, `decision`, `signals`, `evidence`, `actionGraph`, `recommendedActions`, `uncertainty`, `engine`, `metadata` and a detailed `result`. Graph v2 spans are UTF-16 offsets into `result.sanitizedText`; NFC-equivalent quotations are mapped back to original grapheme boundaries. Evidence nodes expose all candidate `spans` (up to 128 with an explicit truncation flag). `span` is only set for a unique match; `ambiguous` indicates repeated text. A matching quote does not prove interpretation. Inspect `engine.providerStatus` to distinguish AI success from fallback.

Responses use `Cache-Control: no-store`. Errors use `{ "schemaVersion": "1.0", "error": { "code": "…", "message": "…" } }`.

| HTTP | Meaning |
| --- | --- |
| 400 | Invalid request, missing idempotency key or AI consent |
| 401 | Invalid, expired or revoked test key |
| 403 | Key scope does not permit the requested analysis mode |
| 402 | Insufficient local test credits |
| 408 | Request body was not received before the deadline |
| 409 | Request identifier already used |
| 413 | Request too large |
| 415 | Request is not `application/json` |
| 429 | A process circuit breaker or local shared guest/key scope limit is full; `Retry-After` gives seconds |
| 500 / 503 | Processing or local service unavailable |

`GET /api/v1/health` reports process health. `GET /api/v1/capabilities` reports feature types, not live provider connectivity. Retrieval and feedback are not implemented. See the [OpenAPI contract](openapi.yaml).

## Abuse protection and limits

The application enforces a bounded request body, a ten-second body-reading deadline, text length, AI consent, provider timeout and output-token cap. A coarse circuit breaker bounds request rate and concurrency per process. In the dedicated local account deployment, guest requests additionally share PostgreSQL limits across replicas: 90/minute and 3,000/day for all analysis, with 4/minute and 24/day for AI attempts. The database admission fails closed. These global counters have no per-client fairness, and they are request ceilings rather than a provider spending budget. The rules-only Docker deployment still has only process-local protection. The code does not trust forwarded IP headers for identity. A 429 does not charge a local credit.

Before any public deployment, implement and test trusted-proxy identity, distributed per-account and per-IP quotas, authentication, signup/login abuse controls, provider-side spending ceilings, monitoring, incident response, and infrastructure-layer request and connection limits. Fail closed when those controls are unavailable. Production AI is blocked; the legacy `AI_EXTERNAL_RATE_LIMIT_CONFIRMED` assertion cannot enable it. See [SECURITY.md](../../SECURITY.md).

## Language and trace metadata

Set `locale` to `cs` or `en` to override `Accept-Language`. Unsupported browser languages fall back to Czech; an invalid explicit locale returns 400. `result.headline` and `result.summary` carry localized copy. Legacy `headlineCzech` and `summaryCzech` remain Czech for compatibility. Decisions, rule IDs, scores, original quotations and UTF-16 spans do not change with locale. English UI support does not turn the Czech rules into a validated English fraud detector.

Requested AI calls include `result.metadata.traceId` and `traceRecorded`. Reported token counts are optional; absent values are unknown. [Trace documentation](../administration/ai-traces.md) describes privacy and storage limits.

Authenticated local requests use [shared PostgreSQL limits](../administration/shared-limits.md): 30 requests/minute per key, a configurable 1–100,000 requests per day per key lineage (default 1,000), 40 per project per minute and 60 per workspace per minute. Rotation revokes the old secret but keeps its scopes, expiration and daily quota lineage. Newly created keys default to `analysis:rules`; `analysis:ai` must be explicitly selected. A shared admission failure prevents credit reservation and provider calls. These controls do not cover anonymous per-IP quotas, provider spending or production authentication. Outside the local account deployment, AI requests return a rules result with `UNAVAILABLE` status without calling a paid provider.
