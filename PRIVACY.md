# Privacy and data flow

The browser attempts to remove selected identifiers and URL paths, queries, fragments and credentials. This is best-effort matching, not anonymization. Names, addresses, unusual identifiers, URL hosts and other sensitive content may remain. The user can edit and must confirm the preview before sending. A direct API caller can send raw input; the server also sanitizes it, but this does not prevent transmission to the server.

The application has no message database and does not deliberately log request text. A hosting provider or intermediary may retain technical data; review its actual configuration before deployment. If AI is requested, consented to and enabled by the operator, the server sends the remaining sanitized text to OpenLux and its upstream model provider, including URL hosts. `store: false` is sent, but relay and upstream retention and processing depend on applicable terms and settings; this is not a zero-retention guarantee. No claim of GDPR compliance is made without an appropriate assessment.
